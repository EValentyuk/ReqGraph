# Журнал ReqGraph

Слой памяти с поисковым доступом: подробности работы, которые не попадают в лог. Не читается целиком - ищется. Новое дописывается снизу.

## 2026-09-25 22:30 · langgraph · В LangGraph 1.2 сбой разбора structured output по умолчанию не повторяется, а pydantic в состоянии требует разрешения

Ключи: langgraph 1.2.12, RetryPolicy, retry_on, default_retry_on, OutputParserException, ValidationError, allowed_msgpack_modules, JsonPlusSerializer, InMemorySaver, interrupt, Command, add_edge список

**Проверили.** Исходник `default_retry_on`: для ValueError, TypeError, LookupError и ещё ряда исключений он возвращает False. OutputParserException и ValidationError наследуют ValueError, поэтому ответ модели, не прошедший схему, по умолчанию не повторяется.
**Решение.** Свой `retry_on`: OutputParserException и ValidationError повторять, остальное отдавать `default_retry_on`. Тест `test_broken_model_output_is_retried`.
**Выяснили.** Pydantic-модель в состоянии при чтении чекпойнта даёт предупреждение «Deserializing unregistered type… will be blocked in a future version». Лечится `JsonPlusSerializer(allowed_msgpack_modules=[(модуль, класс)])` в `InMemorySaver(serde=...)`.
**Проверили.** На макете: `add_edge(["a", "b"], "c")` ждёт оба параллельных узла; interrupt виден в stream как ключ `__interrupt__`, в invoke – в результате; при `Command(resume=...)` узел выполняется с начала.
